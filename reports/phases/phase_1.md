# Phase 1 — Data Audit, Splits Partitioning, and Annotation Design

## Objectives and scope
The objective of Phase 1 is to establish a verified, leak-free, reproducible experimental foundation for **ReqMind AI** in accordance with `Base docs/ReqMind_AI_Implementation_Roadmap.md`:
- Locate, audit, and document the PROMISE FR/NFR requirements dataset (provenance, class balance, record schema, licensing).
- Perform data exploration and distributional analysis (documented in notebook and plots).
- Formulate conservative preprocessing and normalization policies (mandatory preservation of negations, modals, and numbers).
- Partition the dataset into frozen, stratified **Train (70%)**, **Validation (15%)**, and **Test (15%)** splits using a deterministic seed (`seed=42`).
- Execute automated leakage checks confirming zero exact (case-insensitive) textual overlap across splits.
- Formulate operational annotation rubrics and provide **synthetic draft fixtures** for ambiguity (85 items) and duplicate pairs (55 pairs). These are NOT human gold annotations (see limitations).
- Implement automated unit tests verifying split sizes, stratification integrity, leakage absence, and offset validity.

## Data provenance and preprocessing decisions
1. **Provenance:** PROMISE Software Engineering Repository (Cleland-Huang et al., 2007). 969 records across 47 project specifications.
2. **Class Balance:**
   - Functional (`F` -> `FR`): 444 records (45.82%)
   - Non-Functional (`not F` -> `NFR`): 525 records (54.18%)
   - 12 fine-grained categories: `F` (444), `SE` (125), `US` (85), `O` (77), `PE` (67), `LF` (49), `A` (31), `MN` (24), `SC` (22), `FT` (18), `L` (15), `PO` (12).
3. **Conservative Normalization (Rule 4):**
   - Retain negations (`not`, `never`, `no`): critical for security constraints and hard negative identification.
   - Retain requirement modal verbs (`shall`, `must`, `should`, `may`): indicates normative obligation level.
   - Retain numbers and units (`99.95%`, `200ms`, `5 MB`): needed to differentiate testable specifications from vague claims.

## Known limitations / errors
1. **No human gold annotations yet.** PROMISE only labels FR/NFR. The files in `Data/annotations/` are synthetic drafts; the templated items are near-duplicates of each other and would inflate any metric. Roadmap Rule 1 forbids presenting them as ground truth. **Before Phases 4–5 report metrics, they must be replaced/reviewed by the team (target 80–150 ambiguity items, 50–100 pairs, second-annotator subset).**
2. **Project-level leakage not prevented.** The split is stratified-random, so requirements from the same specification appear in train and test. Phase 3 scores may be optimistic vs unseen projects; a project-grouped split should be reported as a secondary evaluation.
3. **Near-duplicate check not done.** Only exact case-insensitive matches were checked; no fuzzy/embedding near-duplicate detection before splitting.
4. **Class imbalance:** `PO` (12) and `L` (15) are small; use macro-F1 in Phase 3.
