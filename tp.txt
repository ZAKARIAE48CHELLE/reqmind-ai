1. Présentation du projet
Contexte : une bibliothèque universitaire dispose d’un catalogue de livres et de documents numériques.
L’objectif est de développer un assistant capable d’aider l’étudiant à rechercher des ressources, poser
des questions en langage naturel, résumer des documents et recevoir des recommandations.
L’application doit combiner des fonctionnalités classiques avec des fonctionnalités intelligentes. L’IA ne
remplace pas la logique métier : elle constitue une couche spécialisée intégrée à l’architecture.
Fonctionnalités attendues
• Recherche de livres : recherche classique dans le catalogue.
• Question en langage naturel : l’étudiant interroge l’assistant.
• Résumé de document : génération d’un résumé à partir d’un document.
• Recommandation : proposition de documents pertinents.
• Historique : consultation des questions et interactions précédentes.

Avant de coder, produire une analyse fonctionnelle courte et structurée.

• Acteurs : étudiant, administrateur/bibliothécaire, services internes.
• Besoins : rechercher, questionner, résumer, recommander, consulter l’historique.
• Fonctionnalités : distinguer les traitements classiques des traitements IA.
• Données : utilisateurs, livres, auteurs, catégories, documents, historique, embeddings, résultats IA.
• Contraintes : sécurité, temps de réponse, qualité des réponses, disponibilité.

4. Étape 2 — Conception de l’architecture
Produire trois représentations complémentaires :
• Diagramme de composants : Frontend, Backend/API, services métier, AI Service, base de données,
Vector DB et LLM.
• Architecture en couches : Interface → Logique métier → Intelligence → Données.
• Flux de données : montrer comment une question circule depuis l’utilisateur jusqu’à la réponse.
Questions de conception
• Pourquoi la logique métier ne doit-elle pas dépendre directement de l’interface ?
• Pourquoi utiliser une base vectorielle pour le RAG ?
• Quelles données doivent rester dans PostgreSQL ?
• Quel composant peut être remplacé sans modifier toute l’application ?

6. Étape 4 — Conception de l’API REST
Créer au minimum les endpoints suivants :
POST /api/questions
GET   /api/books
GET   /api/history
POST /api/summarize
Exemple de requête
POST /api/questions
{
  "question": "Quels livres parlent de cybersécurité ?",
  "user_id": 15
}
Exemple de réponse
{
  "answer": "Voici les documents pertinents...",
  "sources": ["doc_12", "doc_31"],
  "processing_time_ms": 1850
}
À prévoir également : validation des entrées, codes HTTP cohérents, authentification, gestion des
erreurs et journalisation.
